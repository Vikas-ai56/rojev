# v2 plan: generalization to new compositions (research brief, 2026-10-23)

Scope set by the user: (1) new compositions of known skills, each step leaving the next doable; (2) new objects / scenes
as its byproduct. Not new verbs or embodiments yet. 1–2 A100/H100, public data only, 1 month (2 at most), rojev shell
(owner, guard, runtime, lanes) kept; S1/S2 models and their interface may change.

## Verdict
**S1-centred v2: XR-1 runs the whole task; S2 becomes a trained critic (progress / done, capability, next-step
feasibility) that verifies and recovers, and decomposes into atomic sentences only where a week-1 test shows XR-1
obeys them.** Train S2 heads first (cheap, LoRA); train S1 (seams, skill alignment) only if the week-1 gates say the
seams, not supervision, are the limit. Latent S2→S1, JEPA control and VLA RL are month 2+.

Confidence: high that completion + verification is the first build (v1 failure + all sources agree); medium on how
much decomposition adds over flat XR-1 (decided by gate G1); low on any SO-101 transfer number this month.

## 1. Zoom out: what "new compositions" needs
| Capability | Who owns it | Evidence it matters |
|---|---|---|
| Understand the goal, pick skills S1 has | S2 (capability) | π0.5: GPT-4 picking from a label list scored worst; trained HL best ([2504.16054](https://arxiv.org/html/2504.16054)) |
| Execute each skill from the states other skills leave | S1 (seams) | Chain success 0.885 → 0.076 over two seams, from displaced drawers / objects ([Restore, Don't Retry](https://neurips.cc/virtual/2026/162913)); BOSS −34…−67 % ([2502.15679](https://arxiv.org/abs/2502.15679)) |
| Know a step / task is done | S2 (completion) | False "done" is the dominant hierarchical failure; false "not done" costs little ([2606.10267](https://arxiv.org/html/2606.10267)); our run 5 |
| Detect failure, recover | S2 (verify) + S1 (retry) | Frozen-VLA layers gain mostly here: CheckVLA +8.5 on RoboCasa365 ([2607.26789](https://arxiv.org/abs/2607.26789)), PhyAgentOS +8–9 ([2607.16636](https://arxiv.org/html/2607.16636)) |
| Reusable skill representations | S1 (training) | CRAFT: π0.5 on held-out skill combinations 8.4 → 84.2 %, naive segment chaining 0.3–25.7 % ([2610.00524](https://arxiv.org/html/2610.00524v1)) |

Zoom in: the binding number is XR-1's own. On RoboCasa365 it scores 32.1 % on Composite-Unseen *zero-shot* (trained on
the official pretrain set only; paper: "the unseen composite tasks provide a zero-shot evaluation"), every other
model ≤ 14.9 % ([2607.15330](https://arxiv.org/html/2607.15330), Table 3; vendor number). So S2 must beat XR-1 on the
whole-task sentence, not π0.5's 1.2 %. Our parity (18/20) covered 3 atomic-seen + 1 composite-seen task: Composite-Unseen
was never run in our harness.

## 2. The references named
- **π0.7** (verified, closed; [blog](https://www.pi.website/blog/pi07), [paper](https://www.pi.website/download/pi07.pdf)):
  "new tasks" = recombining skills through language, not new verbs. Short unseen tasks work zero-shot; long ones
  (air fryer, bagel) only with step-by-step human coaching, then a high-level policy fine-tuned on the coaching
  transcripts reaches coaching-level progress with no new action data. Unseen tasks 60–80 %. Diversity of data is the
  cause by their own ablation. Take: rich S1 prompt (subtask + quality / mistake metadata, dropout), S2 trained on
  coaching transcripts. Leave: the 14B subgoal-image world model (1.25 s), proprietary data scale.
- **Eka Robotics VFA** (company verified, method not): vision + force, sim RL, pick throughput claims; no paper,
  nothing open. Take nothing now; force matters later for contact steps (SO-101 has only motor current).
- **JEPA** (verified, open, MIT): V-JEPA 2-AC plans zero-shot pick-and-place 65–80 % with goal *images* at ~16 s per
  action ([2506.09985](https://arxiv.org/html/2506.09985)); RoboJEPA (Oct 2026, RoboCasa365 in its data) loses to π0.5
  on pick-and-place 27 vs 53 % ([2610.10515](https://arxiv.org/abs/2610.10515)). Not a controller for us. Possible
  use: V-JEPA 2.1 embedding distance as a feature of the done / feasibility critic (one encoder pass).

## 3. v2 architecture (rojev shell unchanged)
```
user ─▶ owner ─▶ interaction lane: Jev (OneJev typed acts; REVISE = choose a canonical sentence, SayCan-scored)
              └▶ planning lane: Supervisor (new)  ◀── Critic (new, one Qwen3-VL-4B, three heads)
                     │  whole-task sentence by default; COMPLETE when done; RETRY / override on stall or failure
                     ▼
              runtime ◀── S1Runner ◀── XR-1 (frozen month 1; fine-tuned only if G2 fails)
```
- **Critic** (replaces the verifier behind `StepWatcher`): from the newest frames + short history + a sentence ℓ:
  `progress(ℓ)`, `done(ℓ)`, `Q(s, ℓ)` = P(XR-1 succeeds on ℓ from here). Same model answers capability (Q now) and
  next-step feasibility (Q at a step's end state for the next ℓ).
- **Supervisor** (planning lane decider): issues the whole-task sentence; on `done` → COMPLETE (fixes run 5); progress
  flat for a window or a failure → RETRY, or an atomic override (only if G1 passes); never moves on without `done`.
- **Capability list**: the human300 task sentences (`extract_subtask_vocab.py` pattern) — REVISE and overrides choose
  from it: score = P_Jev(ℓ | utterance) × Q(s, ℓ); nothing fits → ASK, logged ("no sentence fits" is a finding).
- Text interface stays: no clean text-vs-latent ablation exists at equal S1 (VLA-OS: language-only plans *below* flat,
  [2506.17561](https://arxiv.org/html/2506.17561v1)); latent requires training S1 jointly.

## 5. Training recipe
| Head | Base | Labels | Negatives | Compute (est.) | Metrics |
|---|---|---|---|---|---|
| done / progress | Robometer-4B, LoRA | done = simulator success predicate per frame (gap band before first success unlabelled); progress = stage-aware t/T from per-object predicates (SARM) | XR-1 failures, post-success frames, rewinds, mismatched sentence = 0 | 1–2 days on 1 H100 | balanced acc, false-done (frame + early stop per episode), latency after success, VOC / Kendall τ |
| Q(s, ℓ) | same backbone, scalar head | success fraction of K = 3–5 XR-1 rollouts from s with ℓ (Foresight recipe, [2607.16506](https://arxiv.org/html/2607.16506v1)) | absent object / fixture = 0 | rollouts ~3–4 days on 2 GPUs (XR-1 ~0.35–0.5 s / query, est.), 1 day train | AUROC, Brier, ECE vs majority baseline |
| S1 seams (conditional) | XR-1 RoboCasa365, full FT | human300 + chained end states (Restore-style) | — | 2 × H100, ZeRO; hours unknown | G2 gap closed, atomic success unchanged |
Rules: hold out Composite-Unseen and unseen kitchens from all training, threshold and model selection; human300-only
results reported separately (leaderboard-clean); data passes `model-bringup/checklist.md`; live data before the
2026-10-22 render fix is not used.

## 5b. v1 limits this build must remove (carried from `task_choice.CanonicalTask`, 2026-10-24)
- Only listed tasks: REVISE chooses among the trained sentences given for the run, else asks. v2 adds the rewrite
  fallback (new compositions in S1's trained style), confirmed or gated by Q.
- No feasibility check: a listed task is chosen even if it cannot run in the current state. v2: Q(s, ℓ) filters it.
- Hand-written list: v2 shortlists from the 4,740 trained sentences (human300 `meta/tasks.parquet`) by scene objects.
